# S0 — execution/recovery feasibility spike

Tracked by [#1](https://github.com/mhingston/pits/issues/1), [#2](https://github.com/mhingston/pits/issues/2), [#3](https://github.com/mhingston/pits/issues/3).

## Intent

This branch is a **draft spike**, not a validated implementation. It co-locates
PiHarness and Sandbox 1.0 in one Durable Object and prototypes process intents
and checkpoint/restore. No Cloudflare live failure-injection deployment has been performed. A GitHub
Actions validation workflow now checks dependency installation, generated
Wrangler types, unit/shell-protocol tests, and TypeScript. Do not merge until issues #1–#3 meet their gates.

## Trust boundaries

- Durable Object SQLite records command intent, active-command gate, receipts,
  container boot ID, and committed workspace-checkpoint metadata.
- Container runs with `enableInternet: false` for S0 and has no provider or
  GitHub credentials.
- Container-local `mkdir` reservations guard against duplicate launches
  *within the same boot*; they are deliberately outside backed-up workspace.
- A new boot invalidates the old container command identity. We never blindly
  replay an in-flight command on the new instance.
- A non-atomic R2 backup plus SQLite metadata update is treated as a two-phase
  protocol. We can only restore a **committed** backup handle.
- Cloudflare Lifecycle is the only owner of the Durable Object alarm. No
  custom `setAlarm` call is allowed.

## Isolated Cloudflare test preparation

The dedicated test config is `wrangler.s0-test.jsonc`; the default `wrangler.jsonc`
continues to describe `pits-s0`. The test config binds a separate
`pits-s0-test-backups` bucket and defaults both destructive fault injection and
the deterministic model fixture to **off**. It does not enable the paid plan or
raise container resources. Check `npx wrangler whoami` and the account's plan
first; stop if Workers Paid / Containers are not already enabled until the
account owner has reviewed the billing impact.

```sh
npx wrangler r2 bucket create pits-s0-test-backups
npx wrangler deploy --config wrangler.s0-test.jsonc
npx wrangler secret put PITS_API_TOKEN --config wrangler.s0-test.jsonc
```

`secret put` prompts on stdin; do not put the secret in a command argument,
repository file, test artifact, or PR comment. Generate a 32-byte random value
locally (for example, `openssl rand -hex 32`) and paste it at the prompt.
After deployment, restrict the test hostname to the operator with Cloudflare
Access before sending test requests. The bearer token remains required as a
second check. The container has no internet and receives no GitHub credentials.

After Access is in place, set `PITS_URL` to the isolated `pits-s0-test` Worker
hostname and provide the bearer token through the local process environment
without shell tracing. If Access uses a browser session, its
`CF_Authorization` value can be provided locally as `PITS_ACCESS_COOKIE`; the
script sends it only as a request cookie, redacts it, and removes it from child
process environments. The repeatable suite writes only synthetic test IDs,
outcomes, hashes, timings, and redacted Worker logs. It enables the two test
switches for the run, redeploys while a command is active to observe deployment
recovery, repeats the intent/reservation/launch/receipt crash windows 10 times
each, and redeploys with both switches **off** in `finally`, including when a
test fails:

```sh
PITS_ITERATIONS=10 npm run test:integration
```

The script rejects localhost URLs. It tests the Faux pi-ai provider, not a
billable model. It captures `wrangler tail` output in a separate redacted JSONL
file. Do not set `PITS_ENABLE_MODEL`; a real-model request is not needed for S0.
If the test process is forcibly killed before `finally` runs, immediately run
the switches-off deploy command below before leaving the test Worker online.

After preserving the local evidence, remove the disposable Worker and its
dedicated backup bucket. This also removes any orphaned R2 upload from an
interrupted backup:

```sh
npx wrangler deploy --config wrangler.s0-test.jsonc \
  --var PITS_ENABLE_FAULTS:false --var PITS_ENABLE_FIXTURE:false
npx wrangler delete pits-s0-test
npx wrangler r2 bucket delete pits-s0-test-backups
```

Do not run the cleanup commands against a non-disposable Worker or bucket.

## API sketch

```sh
# Endpoint is always authenticated, except /health.
curl -H "Authorization: Bearer $PITS_API_TOKEN" "$PITS_URL/api/state"
curl -X POST -H "Authorization: Bearer $PITS_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"id":"probe-1","command":"echo one >> /workspace/pits/marker.txt"}' \
  "$PITS_URL/api/probe"
curl -X POST -H "Authorization: Bearer $PITS_API_TOKEN" \
  "$PITS_URL/api/checkpoint"
```

## Must-pass injected failure tests

1. Repeat the same `id` with the same payload. Observe **one** appended
   marker, not just one final file (`touch` would miss duplication).
2. Restart/redeploy the Task DO during an active command; verify the container
   boot stays the same, and reattach/poll collects exactly one exit result.
3. Inject a DO abort before intent, after intent, after `mkdir`, immediately
   after launch, after process exit but before receipt, and after receipt but
   before response delivery.
4. Destroy the container mid-command. The replay must say **lost**, must not
   re-dispatch, and must block new edits until a known checkpoint is restored.
5. Restore the last committed backup; compare Git status and file hashes
   against the checkpoint's recorded state.
6. Interrupt backup before metadata commit. Previous checkpoint remains valid.
7. Quiescence: an in-flight command blocks both another mutation and backup.
   S0 accepts only a bounded list of foreground coreutils commands, simple
   workspace file operations, and `&&`; shell interpreters, pipes, expansions,
   redirections outside `/workspace/pits`, and background forms are rejected.

## Known blockers/gaps to review before deploy

- Test the actual PiHarness + native container resource sharing and the exported
  DirectoryBackupGateway in the same DO.
- Verify that the background-process recipe works with the pinned Alpine image
  and container execution paths, including boot identity and end-of-process
  receipt durability.
- An `unknown` command fails closed for additional mutations, but the
  original task ID may continue observing its *existing* process and collect
  a late exit receipt. Never relaunch after an uncertain dispatch. If the
  process cannot be classified and settled, manual reconciliation remains required.
- The shell endpoint intentionally does not implement general shell access.
  The executable command-policy regression test checks the allowed grammar
  and rejects common fork, background, pipe, substitution, and path-escape
  forms. The assumption remains limited to files created through this S0 API;
  the runner is not a security boundary for arbitrary preloaded workspace data.
- The prototype's checkpoint record is anchored to the last shell-command ID;
  a proper Pi transcript entry anchor, Git state and generation are still TODO.
- The repeatable fault-injection suite is implemented, but it has not yet run
  against a *real Cloudflare deployment*.
- A deterministic `@earendil-works/pi-ai` Faux provider is enabled only by the
  test config. It issues one bounded `sandbox_bash` tool call and has zero
  model cost. `/api/ask` remains separately gated by `PITS_ENABLE_MODEL`.
- Check that the runner's SQLite transaction boundaries and container ownership
  meet the expected lost/unknown semantics under concurrent HTTP calls.
- Restore after unknown work must explicitly reconcile side effects before a
  resumed agent writes; merely restoring files does not undo external effects.

## Current fail-closed recovery protocol

- Shell command IDs are hashes of Pi task IDs (or a manual test probe ID).
  Repeated command IDs with **different payloads** are rejected, including
  when a previous successful receipt exists.
- The Pi tool remains `replay: "unsafe"` until real crash tests pass. The
  manual `/api/probe` path tests the adapter without relying on an LLM.
- The working directory is `/workspace/pits`, created at runtime. The
  reservation directories live outside it and are not included in backups.
- Checkpoints capture the sequence number of the last completed command.
  On restoration, receipts for commands completed *after* the checkpoint,
  but *before* restoration, become explicitly **lost**; they are never
  silently presented as still applicable. New commands after reconciliation
  have later sequence numbers and are allowed.
- A restored workspace has `reconciliationRequired: true` until a human
  checks it and acknowledges the exact backup ID. This is **not** automatic
  consistency verification or a transcript-entry checkpoint.

## Read-only evidence and reconciliation

All endpoints except `/health` require `Authorization: Bearer <PITS_API_TOKEN>`.

```sh
# View recovery and checkpoint metadata
curl -H "Authorization: Bearer $TOKEN" "$BASE/api/state"

# Inspect a small file without enabling workspace mutations
curl -H "Authorization: Bearer $TOKEN" "$BASE/api/evidence?path=marker.txt"

# After inspecting restored state, acknowledge its exact checkpoint ID
curl -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  --data '{"checkpointId":"<backup-id-from-restore>"}' \
  "$BASE/api/reconcile"
```

`/api/evidence` permits a bounded read of a relative path under the workspace.
The paths and text in this endpoint are synthetic test data only. Cloudflare
Access must gate the Worker before remotely enabling any shell execution.

## Remaining S0 blockers

1. Confirm PiHarness and `ctx.container` co-location in a real deployment,
   including alarm ownership and deployment recovery.
2. Run the live quiescence regression against Cloudflare; the command subset is
   enforced locally and the remote checkpoint gate still needs observation.
3. Bind checkpoint metadata to an actual Pi transcript entry and Git tree
   fingerprint, not just the latest completed command sequence.
4. Run the dedicated suite for ≥10 controlled repetitions of intent,
   after-mkdir/before-PID, after-launch, and after-exit/before-SQL-receipt
   windows. The 60-second DO reset, active replacement, redeploy, and
   120-second deadline cases currently run once per suite invocation.
5. Configure an R2 lifecycle rule for disposable backup objects and
   capture backup/restore timing, size, and error reports.

Do **not** close issues #1–#3 or merge PR #8 solely on green typechecks.

### Confirmed fixes in this branch

- Pi Durable consumes a tool result from `content`; returning it under
  `output` dropped the command receipt from the transcript. The S0 tool now
  returns the durable result through `content`.
- A DO abort during backup skips `finally` and otherwise strands the durable
  maintenance flag. A fresh DO constructor clears that stale flag; the SDK
  documents that its backup helper exits when the DO restarts. Live validation
  is still required for the reset timing on Cloudflare.
- A process-observation/launch error used to escape as an API error without a
  durable process classification. It now settles to `lost` only after a changed
  container boot is observed; otherwise it remains `unknown`, keeps the active
  lock, and never authorizes a second dispatch. The pure decision is covered by
  a local regression test; container-failure behavior still needs live proof.
- S0 shell requests now pass a bounded command allowlist. This makes the
  foreground-only assumption executable instead of relying on substring
  filters. The regression test rejects background jobs, interpreters, shell
  composition, path escapes, and total sleep time over 180 seconds.
- Test-only DO abort points and a deterministic model fixture are gated behind
  `PITS_ENABLE_FAULTS` and `PITS_ENABLE_FIXTURE`; the isolated config defaults
  both switches off.

## Copilot review corrections (10 Oct 2026)

- After the polling deadline, retain the active-command lock and persist a
  `no-redispatch` marker rather than incorrectly treating a still-running
  process as workspace loss. A request with the **same command ID** can
  reattach or collect a later exit, releasing the active lock with the
  receipt; a different command stays blocked. A disappearing same-boot
  reservation after an unknown result **cannot** trigger dispatch again.
- Container replacement and workspace restore remain separate states:
  `restore-required` / `reconciliation-required` block even same-ID
  observation, and require restoring a verified checkpoint and human review.
- CI now uses only `npm ci` against the checked-in `package-lock.json`;
  the temporary write-enabled lockfile bootstrap has been removed.
- Unit tests cover same-ID re-observation, late completion classification,
  other-command exclusion, and no redispatch after uncertain execution.
  **Live Cloudflare failure injection is still required before S0 is accepted.**
