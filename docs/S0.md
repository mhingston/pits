# S0 — execution/recovery feasibility spike

Tracked by [#1](https://github.com/mhingston/pits/issues/1), [#2](https://github.com/mhingston/pits/issues/2), [#3](https://github.com/mhingston/pits/issues/3).

## Intent

This branch is a **draft spike**, not a validated implementation. It co-locates
PiHarness and Sandbox 1.0 in one Durable Object and prototypes process intents
and checkpoint/restore. No Cloudflare live failure-injection deployment has been performed. A GitHub
Actions validation workflow now checks dependency installation, generated
Wrangler types, unit/shell-protocol tests, and TypeScript. Do not merge until issues #1–#3 meet their gates.

## Trust boundaries

- Durable Object SQLite records command intent, active-command gate, receipts,
  container boot ID, and committed workspace-checkpoint metadata.
- Container runs with `enableInternet: false` for S0 and has no provider or
  GitHub credentials.
- Container-local `mkdir` reservations guard against duplicate launches
  *within the same boot*; they are deliberately outside backed-up workspace.
- A new boot invalidates the old container command identity. We never blindly
  replay an in-flight command on the new instance.
- A non-atomic R2 backup plus SQLite metadata update is treated as a two-phase
  protocol. We can only restore a **committed** backup handle.
- Cloudflare Lifecycle is the only owner of the Durable Object alarm. No
  custom `setAlarm` call is allowed.

## API sketch

```sh
# Endpoint is always authenticated, except /health.
curl -H "Authorization: Bearer $PITS_API_TOKEN" "$PITS_URL/api/state"
curl -X POST -H "Authorization: Bearer $PITS_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"id":"probe-1","command":"echo one >> /workspace/pits/marker.txt"}' \
  "$PITS_URL/api/probe"
curl -X POST -H "Authorization: Bearer $PITS_API_TOKEN" \
  "$PITS_URL/api/checkpoint"
```

## Must-pass injected failure tests

1. Repeat the same `id` with the same payload. Observe **one** appended
   marker, not just one final file (`touch` would miss duplication).
2. Restart/redeploy the Task DO during an active command; verify the container
   boot stays the same, and reattach/poll collects exactly one exit result.
3. Simulate interrupted dispatch: crash after durable intent, after
   `mkdir`, after launcher exit, and after exit receipt.
4. Destroy the container mid-command. The replay must say **lost**, must not
   re-dispatch, and must block new edits until a known checkpoint is restored.
5. Restore the last committed backup; compare Git status and file hashes
   against the checkpoint's recorded state.
6. Interrupt backup before metadata commit. Previous checkpoint remains valid.
7. Quiescence: in-flight commands (and any background descendants) must be
   absent before a backup is taken.

## Known blockers/gaps to review before deploy

- Test the actual PiHarness + native container resource sharing and the exported
  DirectoryBackupGateway in the same DO.
- Verify that the background-process recipe works with the pinned Alpine image
  and container execution paths, including boot identity and end-of-process
  receipt durability.
- An `unknown` command currently fails closed and requires manual
  reconciliation; it is not an automatic self-healing mechanism.
- The S0 runner assumes **no detached processes**. Shell commands are not yet
  restricted sufficiently to enforce that assumption.
- The prototype's checkpoint record is anchored to the last shell-command ID;
  a proper Pi transcript entry anchor, Git state and generation are still TODO.
- Fault-injection tests against a *real Cloudflare deployment* are not yet written.
- No synthetic model provider is wired; the model endpoint currently uses a
  Workers AI coding model and may incur inference cost.
- Check that the runner's SQLite transaction boundaries and container ownership
  meet the expected lost/unknown semantics under concurrent HTTP calls.
- Restore after unknown work must explicitly reconcile side effects before a
  resumed agent writes; merely restoring files does not undo external effects.

## Current fail-closed recovery protocol

- Shell command IDs are hashes of Pi task IDs (or a manual test probe ID).
  Repeated command IDs with **different payloads** are rejected, including
  when a previous successful receipt exists.
- The Pi tool remains `replay: "unsafe"` until real crash tests pass. The
  manual `/api/probe` path tests the adapter without relying on an LLM.
- The working directory is `/workspace/pits`, created at runtime. The
  reservation directories live outside it and are not included in backups.
- Checkpoints capture the sequence number of the last completed command.
  On restoration, receipts for commands completed *after* the checkpoint,
  but *before* restoration, become explicitly **lost**; they are never
  silently presented as still applicable. New commands after reconciliation
  have later sequence numbers and are allowed.
- A restored workspace has `reconciliationRequired: true` until a human
  checks it and acknowledges the exact backup ID. This is **not** automatic
  consistency verification or a transcript-entry checkpoint.

## Read-only evidence and reconciliation

All endpoints except `/health` require `Authorization: Bearer <PITS_API_TOKEN>`.

```sh
# View recovery and checkpoint metadata
curl -H "Authorization: Bearer $TOKEN" "$BASE/api/state"

# Inspect a small file without enabling workspace mutations
curl -H "Authorization: Bearer $TOKEN" "$BASE/api/evidence?path=marker.txt"

# After inspecting restored state, acknowledge its exact checkpoint ID
curl -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  --data '{"checkpointId":"<backup-id-from-restore>"}' \
  "$BASE/api/reconcile"
```

`/api/evidence` permits a bounded read of a relative path under the workspace.
The paths and text in this endpoint are synthetic test data only. Cloudflare
Access must gate the Worker before remotely enabling any shell execution.

## Remaining S0 blockers

1. Confirm PiHarness and `ctx.container` co-location in a real deployment,
   including alarm ownership and deployment recovery.
2. Fully implement a process-group/detached-child quiescence check or restrict
   the entire S0 corpus to known foreground commands. The current shell
   pattern rejection is only a guardrail, **not** reliable child cleanup.
3. Bind checkpoint metadata to an actual Pi transcript entry and Git tree
   fingerprint, not just the latest completed command sequence.
4. Run ≥10 controlled DO/container interruption tests, including the
   after-mkdir/before-PID and after-exit/before-SQL-receipt windows.
5. Configure an R2 lifecycle rule for disposable backup objects and
   capture backup/restore timing, size, and error reports.

Do **not** close issues #1–#3 or merge PR #8 solely on green typechecks.
